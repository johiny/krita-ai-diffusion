# RTX VSR upscaling with the official NVIDIA VFX node pack

Date: 2026-11-07
Branch: `rtx-vsr-native` (base `828b70c` = `origin/main`, tag `v1.54.0-pre`)

## Goal

Restore NVIDIA RTX Video Super Resolution as an upscaler in the Upscale workspace, implemented
against the **official Comfy-Org node pack** (`Comfy-Org/ComfyUI_Nvidia_VFX_Nodes`, node id
`RTXVideoSuperResolution`) and driven by the **node schema exposed at runtime**, so the feature
keeps working across pack versions without local forks or duplicate wrapper nodes.

## Non-goals

- RTX Video HDR and RTX Video Frame Generation nodes (separate future work).
- Tiled/diffusion refinement pipelines beyond what already exists (VSR only replaces the
  pre-upscale step, exactly like an ESRGAN model does).
- Pushing, releasing, or publishing the branch.

## Contract

### C1 - Detection
`ClientModels.upscalers` gains the entry `"RTXVideoSuperResolution"` **only if** ComfyUI reports a
node of that class with a `quality` combo input. Nothing is hardcoded about pack versions.

### C2 - Schema-derived capabilities
`ClientModels.rtx_vsr` is `None` when the node is absent, otherwise a JSON-serializable dict:

```json
{
  "quality": ["BICUBIC", "LOW", "...", "DEBLUR_ULTRA"],
  "default_quality": "ULTRA",
  "has_strength": true
}
```

`quality` is read from the node's `input.required.quality` options, `default_quality` from its
`default` (fallback: first option), `has_strength` is `"strength" in inputs`. It survives
`ClientModels.from_dict` so remote clients keep the same UI.

### C3 - Prompt generation
For `UpscaleInput.model == "RTXVideoSuperResolution"` the pre-upscale node is:

```
RTXVideoSuperResolution
  images              <- IMAGE link
  resize_type         = "scale by multiplier"
  resize_type.scale   = clamp(factor, 1.0, 4.0)
  quality             = UpscaleInput.rtx_quality
  strength            = UpscaleInput.rtx_strength   (only when the node declares it)
```

- `image_encoding` and any other schema defaults are left to ComfyUI's defaults.
- After the node, if `factor > 4.0` or the target extent is not a multiple of 8 (VSR rounds to
  multiples of 8), an `ImageScale` (lanczos) node resizes to `image.extent * factor`.
- Non-VSR upscalers keep the existing `UpscaleModelLoader` + `ImageUpscaleWithModel` path
  unchanged, including the `factor != 4.0` resize rule.

### C4 - Workspace state
`UpscaleWorkspace` gains `rtx_quality` (persisted string) and `rtx_strength` (persisted float,
`0.0..1.0`, default `1.0`). They only affect the prompt when the RTX upscaler is selected.

### C5 - UI
In the Upscale workspace, selecting "NVIDIA RTX VSR":
- shows an **RTX Quality** combo populated from `ClientModels.rtx_vsr["quality"]`, labels
  humanized (`DENOISE_LOW` -> "Denoise Low"), preserving the raw value as item data;
- shows an **RTX Strength** slider only when `has_strength` is true;
- both rows hide for every other upscaler, and the quality combo re-populates when the client
  reconnects or models change.

### C6 - No wrapper node
`krita_rtx_vsr_bridge` (the duplicate `KritaRTXVideoSuperResolution` custom node) is no longer
needed by the extension and is removed from the ComfyUI install.

## Acceptance tests

| # | Case | Expected |
|---|------|----------|
| A1 | Node absent from `/object_info` | upscaler not listed, `rtx_vsr is None` |
| A2 | Node 0.1.x schema (quality only) | `quality` = 4 options, `has_strength` false, prompt has no `strength` |
| A3 | Node 0.2.x schema (quality + strength + image_encoding) | 19 options, `has_strength` true, prompt includes `strength` |
| A4 | `factor = 2.0` | `resize_type.scale = 2.0`, no extra `ImageScale` |
| A5 | `factor = 6.0` | `resize_type.scale = 4.0` + `ImageScale` to target |
| A6 | Target extent not multiple of 8 | extra `ImageScale` present |
| A7 | Non-VSR model selected | workflow unchanged (`UpscaleModelLoader` path) |
| A8 | `ClientModels.from_dict` round-trip | `rtx_vsr` preserved |

## Verification

1. `pytest tests/ -q` (full suite) and `ruff check`/format as configured by the repo.
2. Live ComfyUI 0.44.0 + `nvidia_vfx_nodes` 0.2.1 + `nvidia-vfx 0.2.0.0`:
   `/object_info/RTXVideoSuperResolution` must expose `strength` and the 19 quality modes.
3. Real end-to-end upscale submitted through the extension's prompt builder, output dimensions
   equal to `extent * factor`.

## Risks

- VSR rounds output to multiples of 8; mitigated by C3.
- DENOISE_*/DEBLUR_* modes keep input dimensions; they become a no-op resize plus lanczos to the
  requested factor. Documented in the UI tooltip rather than hidden.
- The pack is still a `custom_nodes` extension (there is no core ComfyUI node), so users without
  it see the entry simply absent.
