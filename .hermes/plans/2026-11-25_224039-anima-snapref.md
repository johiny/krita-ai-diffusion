# Anima reference support via SnapRef

Goal: a reference control layer on an Anima checkpoint reaches the sampler through the
`SnapRef` node, so the character/style of the reference image actually affects the result.

## Why

Reference layers work today for SD15/SDXL (IP-Adapter) and Flux (Redux). On Anima they are
dead weight: `apply_ip_adapter()` returns the model untouched for anything that is not
SD15/SDXL-like, and `ControlLayer._update_is_supported()` marks the layer "Not supported for
Anima". The server-side SnapRef package already exposes the node
`SnapRef (MODEL, CLIP, VAE, reference IMAGE, adapter) -> MODEL`.

## Contract

1. **Gate.** `ControlMode.reference` is supported on `Arch.anima` when the connected server
   lists at least one SnapRef adapter in `models/loras` (a filename containing `snapref`).
2. **Insertion.** For every reference control layer, the workflow inserts one `SnapRef` node
   between the checkpoint `MODEL` and the sampler. Several reference layers chain: each node
   wraps the previous model.
3. **Inputs.** `model` (previous link), `clip` and `vae` from the checkpoint load, `image` from
   `control.image.load(w)`, `adapter` resolved from the server list.
4. **Mapping.**
   - `weight_1` = control layer strength (`0..1.5`, `1.0` = as trained). Linear by design;
     SnapRef's `strength` is log-scale and not exposed in v1.
   - `mode` = `cs` (character and style), `fidelity` = `1.0`, `ref_caption` empty,
     `ref_in_uncond` off, `ref_megapixels` `1.0`.
5. **Missing adapter.** No SnapRef adapter on the server: the layer stays unsupported and says
   so, using the existing "The server is missing ..." convention. No node is inserted and no
   invalid combo value reaches the server.
6. **Other architectures.** Unchanged. SD15/SDXL keep IP-Adapter, Flux keeps Redux, Anima
   without reference layers builds exactly the workflow it builds today.

## Non-goals (v1)

- Adapter picker in the UI (first match wins: `snapref_v2a*` preferred, else any `snapref*`).
- `char` / `style` mode selection, `ref_guidance`, `multi_layout`, `image_2` / `image_3`.
- Direct reference support for the inpaint/refine/upscale builders beyond the shared helper.

## Files in scope

- `ai_diffusion/backend/comfy_workflow.py` — `apply_snapref()` node binding.
- `ai_diffusion/backend/workflow.py` — `apply_anima_references()` + call sites.
- `ai_diffusion/backend/resources.py` — optional custom node entry for the package.
- `ai_diffusion/model/control.py` — availability gate for Anima.
- `tests/test_anima_snapref.py` — conformance tests.

## Acceptance tests

| Case | Expected |
| --- | --- |
| Anima + one reference layer + adapter present | one `SnapRef` node, `weight_1` = layer strength, adapter from server list, image from the layer, model chain into the sampler |
| Anima + two reference layers | two chained `SnapRef` nodes |
| Anima + reference layer, no adapter on server | no `SnapRef` node, layer unsupported with the "missing" message |
| Anima without reference layers | no `SnapRef` node (regression guard) |
| SDXL + reference layer | IP-Adapter path untouched, no `SnapRef` |

## Definition of done

Workflow JSON for an Anima job with a reference layer contains a valid `SnapRef` node whose
`adapter` is one of the server's advertised values, the tests above pass, and the plugin copy
in Krita matches the branch.
